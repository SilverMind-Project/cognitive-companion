# Migrations

- Every schema change is a new Alembic revision on top of the current head (`make migration`,
  then review the autogenerated file). The baseline `0001_baseline.py` is frozen.
- `downgrade()` exactly reverses `upgrade()`. Never edit an applied revision, never fold a
  change into the baseline, and never drop and recreate the database: live household data
  must survive every upgrade.
- Confirm one head with `alembic heads`. Detail: the engineering-standards skill,
  `reference/database.md`.
