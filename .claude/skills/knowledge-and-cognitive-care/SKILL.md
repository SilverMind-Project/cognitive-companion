# Knowledge Delivery and Cognitive Care

Patterns and architectural standards for the curated Knowledge Repository, Info Cards, Quizzes, Senior RAG Q&A, and Pipeline Builder knowledge steps (see `/home/sriram/code/nanai/notes/cc/cc-rag.md` for background). For general backend layering, typing, time, logging, and testing rules, follow `/home/sriram/code/nanai/cognitive-companion/.claude/skills/engineering-standards/SKILL.md`. For Vue/Vuetify UI rules, follow `/home/sriram/code/nanai/cognitive-companion/.claude/skills/front-end/SKILL.md`.

## 1. Service-layer ownership (no ORM or MinIO logic in routers)

Routers under `backend/routers/{knowledge.py,info_cards.py,quizzes.py,knowledge_interactions.py,knowledge_layouts.py}` must be thin HTTP adapters: validate input, enforce `require_permission(...)`, extract actor via `actor_from_auth(auth)` (`backend/core/auth.py`), call a service on `app.state`, and return a typed Pydantic `response_model`.

All business logic, status state machines, SQLAlchemy sessions, and MinIO side-effects live in `backend/services/knowledge/`:
- `backend/services/knowledge/ingestion_service.py` (`KnowledgeIngestionService`): document CRUD, image attachment CRUD, single-session chunking and Triton embedding, re-embed retry job, and MinIO prefix cleanup (`knowledge/{doc_id}/`).
- `backend/services/knowledge/info_card_service.py` (`InfoCardService`): info card CRUD, slot image upload/source-image binding/variant rendering via `ImagePipeline`, layout-change re-rendering and `min_images` validation, approval/archival transitions, and delete guards.
- `backend/services/knowledge/quiz_service.py` (`QuizService`): quiz and question CRUD, atomic question reordering, question image upload/source-image binding/variant rendering and presigned URL enrichment, approval validation (at least one question; valid choices for `multiple_choice`; non-empty `expected_answer` for `open_ended`), archival transitions, and delete guards.
- `backend/services/knowledge/interaction_service.py` (`KnowledgeInteractionService`): paginated `{items, total}` queries for `SeniorKnowledgeQuery`, `QuizSession` (with detail and responses), `InfoCardDelivery`, and `TagAnalyticsOut`, using timezone-aware UTC bounds (`datetime.combine(d, time.min, tzinfo=UTC)`). Exposed identically through `backend/routers/knowledge_interactions.py` and MCP tools for BFF/MCP parity.
- `backend/services/knowledge/query_service.py` (`KnowledgeQueryService`): vector similarity search over `approved` document chunks + constrained LLM synthesis + audit logging to `senior_knowledge_queries`.
- `backend/services/knowledge/content_generation.py` (`ContentGenerationService`): LLM-assisted paraphrase, quiz draft generation, single-question regeneration, voice instruction suggestion, and generous open-ended answer grading.
- `backend/services/knowledge/delivery_service.py` (`KnowledgeDeliveryService`): runtime delivery of info cards and quizzes across PWA WebSocket, e-ink (`async_get_object` / `async_upload_bytes`), and Gemini Live voice, plus quiz session lifecycle and pipeline resume.

## 2. Startup validation and single-session ingestion

1. **Startup model-ID validation:** `wire_knowledge` (`backend/bootstrap/knowledge.py`) must verify at startup that `knowledge.answer_model`, `knowledge.paraphrase_model`, and `knowledge.quiz_generation_model` exist in `app.state.llm_model_registry` (or log a structured error / fail fast when configured models do not match `llm.models[*].id` in `config/settings.yaml`). Never reference an unregistered model alias.
2. **Single-session chunk and embed:** `KnowledgeIngestionService._chunk_and_embed` must update `doc.status = "chunked"` (and `doc.updated_at = datetime.now(UTC)`) on a `KnowledgeDocument` row loaded within the same SQLAlchemy `Session` that inserts `KnowledgeDocumentChunk` rows and commits. Never mutate a `KnowledgeDocument` instance attached to an outer uncommitted session, or documents will remain stuck in `'uploaded'` and re-embed every 10 minutes forever.
3. **Commit-before-purge and 409 delete guards:** Before deleting a `KnowledgeDocument`, `InfoCard`, `Quiz`, or `QuizQuestion`, check whether any active rule's `PipelineStep` (`info_card` or `quiz_start`) references the resource, and check whether historical `InfoCardDelivery`, `QuizSession`, or `QuizResponse` rows reference it (`ON DELETE RESTRICT`). If referenced, raise `ConflictError` (HTTP 409) with a clear message instructing the caregiver to archive the resource instead of crashing with an unhandled 500 `IntegrityError`. Purge MinIO prefixes only after `db.commit()` succeeds.

## 3. Multimodal voice + PWA synchronization and voice lifecycle

1. **Always compose with base persona:** Every voice delivery (`deliver_info_card`, `start_quiz_session`, `interactive_prompt`, and `guided_task`) must compose its `voice_instruction` via `VoiceInstructionConfig.compose(step_type, base_instruction=settings.as_str("llm.realtime.system_instruction"), step_override=..., resource_override=...)`. Passing a per-delivery instruction without `base_instruction` wipes out the companion's identity, household context, and tool-calling instructions on Gemini Live reconnect.
2. **Reset voice instruction after delivery:** When a quiz session completes/times out or an info card is dismissed, reset the audio session's active voice instruction back to the base system instruction so the quiz/card persona does not stay stuck on the connection indefinitely.
3. **Enable microphone on voice-interactive delivery:** When `start_quiz_session` or `AgentSessionVoice.speak_step` injects a voice prompt expecting a spoken response from the senior, broadcast `{"type": "enable_microphone"}` over `ws_manager` so `CompanionView.vue` activates audio recording if the microphone is idle.
4. **Synchronize PWA and voice across every question:**
   - `start_quiz_session` must include the first question's multiple-choice options (or open-ended prompt) in the initial voice prompt injected into Gemini Live, and `QuizDialog.vue` must auto-advance from the intro screen to Question 1 when a question payload arrives or after a brief gentle countdown so voice and screen never show different states.
   - `submit_quiz_answer` must lock the `QuizSession` row (`with_for_update()`), reject terminal sessions (`completed`, `abandoned`, `timed_out`), handle duplicate submissions for the same `(session_id, question_id)` idempotently, and return the `next_question` descriptor (`question_ord`, `question_type`, `question_text`, `choices`, `completed`) in its return dict so the `submit_quiz_answer` MCP tool gives Gemini Live everything needed to speak Question N+1 immediately without a second tool call.
   - When `submit_quiz_answer` is invoked from the PWA (`channel="pwa"`), if a realtime voice session is connected (`ws_manager.active_connections`), inject a brief orchestrator update into Gemini Live so the voice assistant knows the senior tapped an answer on screen and speaks the feedback / next question in lockstep.
5. **Quiz timeout safety:** `complete_quiz_session` must cancel the scheduled APScheduler job `quiz_timeout_{session_id}`. The timeout handler must be a module-level function resolving `app.state.knowledge_delivery`, must only transition sessions whose status is still `started` or `in_progress` (never overwriting `completed`), must broadcast a `quiz_timeout` WebSocket event to close `QuizDialog.vue`, and must call `resume_owning_pipeline` so the parked pipeline execution completes cleanly.
6. **Dedupe queries:** Always use `.order_by(QuizSession.completed_at.desc()).limit(1).scalars().first()` (never `.scalar_one_or_none()`) when checking recent completed sessions within `dedupe_hours`.

## 4. Pipeline Builder integration and RAG link

1. **`knowledge_query` step:** The Pipeline Builder connects rules to the curated Knowledge Repository through the `knowledge_query` step (`gate_safe=True`), distinct from `semantic_memory_query` (which queries camera scene observations in `semantic-memory-service`). `knowledge_query` renders `{{ }}` templates in `query_text` and optional `tags`, calls `services.knowledge_query.answer(...)`, and emits `{answer_text, answered_via, top_similarity, source_document_ids, source_chunk_ids, query_id}` in `StepResult.data` (with declared `output_schema`) so downstream `condition`, `llm_call`, `info_card`, `interactive_prompt`, or `notification` steps can consume curated household knowledge via `{{steps.<label>.outputs.answer_text}}`.
2. **Template rendering at delivery time:** `info_card` and `quiz_start` steps must render `{{ }}` templates (`render_template` with `build_template_context(trigger, pipeline_data)` plus `senior_name`) on `card.title`, `card.body_text`, `card.voice_instruction`, `quiz.intro_voice_template`, `quiz.voice_instruction`, and step-level `voice_instruction` overrides before delivery.
3. **Cool-off promotion:** Both `InfoCardStep.execute` and `QuizStartStep.execute` must check `if config.get("trigger_cooloff", True): result_data["_cooloff_triggered"] = True` so rules that deliver info cards or quizzes respect `rule.cool_off_minutes`.
4. **Dedicated step config components:** Every built-in step (`info_card`, `quiz_start`, `guided_task_start`, `knowledge_query`, `interactive_prompt`) must have a dedicated structured Vue config editor under `frontend/src/components/pipeline/steps/` registered in `steps/index.js` with canvas summary `chips` and `STEP_DOT_COLORS` in `stepMeta.js`. Never leave senior-care steps on the raw JSON `GenericPluginConfig.vue` fallback.

## 5. Clinical dementia-care UX standards

1. **Errorless Learning and Gentle Reminiscence mode (`interaction_mode: "gentle" | "standard"`):** Clinical neuropsychological research (Baddeley & Wilson, 1994; Clare et al., 2000; Woods et al., 2018 Cochrane Review on Reminiscence Therapy) demonstrates that overt testing and harsh error feedback ("Incorrect") trigger test anxiety, cortisol elevation, and withdrawal in people with dementia, and can reinforce false memory traces. Quizzes default to `"gentle"` (reminiscence/errorless-learning) mode:
   - Never display harsh red "Incorrect / Wrong" banners or percentage failure scores to the senior.
   - When the senior selects or speaks an unexpected answer in `"gentle"` mode, offer a warm, dignity-preserving cue or conversational reminder using the question's `explanation` ("That's a lovely thought! Here is a little reminder: ...") and allow moving forward comfortably without penalty, while still recording `is_correct` in `quiz_responses` for longitudinal caregiver cognitive-trend tracking.
2. **Multimodal dual-coding (visual + voice):** Seniors with dementia commonly have presbycusis (hearing loss) and reduced working-memory span. Every spoken prompt, info card, quiz question, or RAG answer (`KnowledgeAnswerWidget.vue`, `InfoCardDialog.vue`, `QuizDialog.vue`, and the guided-task companion widget) must pair warm, unhurried audio with high-contrast large typography (`>= 22px` body, `>= 28px` title), clear imagery when available, generous touch targets (`>= 64px` height), and a bounded auto-dismiss timer (`KnowledgeAnswerWidget.vue` defaults to 45s with a manual "Got it" button) so stale dialogs never block the screen forever.
